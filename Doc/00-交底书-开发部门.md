## 2. 产品一句话与边界

**一句话**：面向北美别墅/大宅业主与顾问的**中立有线智能家居购买决策 APP**，帮助完成「是否适配有线集成 → 四品牌对照 → 预算与 RFQ → 找授权集成商 → 移交与施工陪伴」全流程。

**核心品牌（有线控制层）**：Control4、Crestron、Savant、Lutron（照明/遮阳底座常与前三家并存）。

**明确排除 / 边界**：

| 边界 | 说明 |
|---|---|
| 市场 | 以北美（美加）专业集成（CEDIA 类）为主；**排除中国市场**作为本产品范围 |
| 品类 | 专业有线/半有线集成，不是零售 Matter DIY 音箱生态替代品 |
| 同系列产品 | Matter 购买决策 APP、KNX 购买决策 APP 为**同系列姊妹产品**，PRD 副本在 `03-suite-related/`，**非本仓核心** |
| 融合关系 | 本仓 `Doc/06-internet-cases/fusion-hybrid/` 收录 KNX↔四老牌、Matter/Zigbee↔老牌/KNX 的公开融合素材，供「融合建议」模块；不等于把 Matter/KNX APP 全需求并入 X Home Easy |
| 子系统 | `Doc/08-subsystems/` 收录 HVAC/新风/豪华影音/安防/遮阳泳池等与四老牌常见联动的公开方案；即使单篇未点名四品牌，也按「有线控制层最适」角度标注 `control_layer_fit` |

## 5. 各目录详细内容说明

### 5.1 `01-PRD/` — 需求与核实

- **docx / txt**：产品目标用户、主流程（适配→对照→预算→RFQ→找商→移交）、商业假设、合规（CCPA/FTC）、安全边界（不做危险 DIY 接线）。
- **市场核实表.md**：对 PRD 中关键市场说法的逐条核实（已证实 / 部分证实 / 与来源矛盾 / 无法核实）。开发与文案必须以核实结论为准；例如 Control4「项目锁死」已被官方换商流程**否定为笼统说法**（见核实表 X05）。

### 5.2 `02-Doc/00-index/` — 图库索引

- `README.md`：目录体系与阶段 A/B/C 原则。
- `mindmap.md`：知识结构思维导图。
- `progress.json`：收集进度与计数（含本交底写入的 handoff 字段）。
- `phase-A/B/C-log.md`：各阶段工作日志。

### 5.3 `02-Doc/01`–`04` — 四品牌官方层（阶段 A）

每品牌统一子目录：

| 子目录 | 内容 |
|---|---|

| `02-products` | 控制器/面板/照明/影音等公开规格摘要 |
| `03-architecture` | 拓扑、协议、第三方互操作 |
| `04-install-wiring` | 安装与布线公开指南摘要（**停在安全边界**） |
| `05-programming-handover` | 编程工具、项目文件、经销商移交政策 |
| `06-ops-remote` | 远程管理、订阅运维 |
| `07-partner-network` | 找经销商与认证体系 |
| `08-pricing-public` | 公开可见价目（无则记未公开） |

## 6. 推荐使用方法 / 开发接入指南

### 6.1 阅读顺序（强制）

1. 本交底书。  
2. `01-PRD` 中 docx（或 txt）+ **市场核实表** —— 建立事实边界。  
3. `02-Doc/00-index/README.md` + `progress.json`。  
4. 按模块需要导入 jsonl/csv（见下）。

### 6.2 产品信息架构 ↔ 素材映射

| App 模块（建议） | 主数据源 |
|---|---|
| 品牌百科 / 规格与架构 | `02-Doc/01`–`04` + 各 `10-manifest.json` |
| 选型对比 | `05-cross-brand/matrix` + `06/.../design/` + 核实表 X02/X07/X08 |
| 灵感 / 项目案例 | `06-internet-cases/projects` + `experience` + fusion 中 E1/E3 案例 |
| 融合建议（KNX / Matter） | `fusion-hybrid/corpus.jsonl`，卡片优先 `app_takeaway_zh` + `fusion_pattern` |
| 找经销商 | `07-channel-partners/unified/channel-partners-master.csv` |
| 子系统整案（空调/新风/影音/安防等） | `08-subsystems/**/…` 与 `master.corpus.jsonl`，突出 `control_layer_fit` |
| 预算与 RFQ 文案 | PRD + 核实表 X06/X07（**只用区间，标服务商/媒体口径**） |

### 6.3 训练 / RAG 优先级

| 优先级 | 文件 | 说明 |
|---|---|---|
| P0 | `fusion-hybrid/corpus.jsonl` | 194 条结构化融合语料 |
| P0 | `08-subsystems/00-index/master.corpus.jsonl` | 564 条子系统语料 |
| P0 | `channel-partners-master.csv` | 结构化商户检索，不宜整表塞进 LLM 上下文 |
| P1 | 各品牌 `10-manifest.json` + 对应 md 摘要 | 百科与规格 |
| P1 | `06-internet-cases/manifest.json` + 30 篇 md | 案例短摘要 |
| P2 | `*.md` 人类可读全文 | 运营校对、人工审核 |
| 慎用 | `99-raw/` | 噪声大、可能含导航垃圾；仅溯源 |

建议 embedding 字段组合：`title` + `summary_zh` + `training_snippet`（+ 有则 `app_takeaway_zh`）。元数据过滤用 `evidence_tier`、`category`、`brands`、`region`。

### 6.4 字段字典（核心）

| 字段 | 出现位置 | 用法 |
|---|---|---|
| `id` | FH* / SS* | 稳定主键 |
| `source_url` | 几乎全部 | 必显或可点开的出处 |
| `evidence_tier` | E1–E4 | UI 徽章与排序权重 |
| `fetched_on` | 收集日 | 内容新鲜度 |
| `mentions_legacy_brands` | 子系统 | 是否明确点名四老牌；未点名仍可因 `control_layer_fit` 收录 |
| `control_layer_fit` | 子系统 | 「为何推荐由有线控制层统一」的产品句 |
| `app_takeaway_zh` | 融合（部分）/ 子系统 | 卡片主文案 |
| `fusion_pattern` | 融合（第二轮） | 如 KNX 骨干+Control4 UI、Matter 改造叠加等 |
| `source_tier` | 渠道 CSV | 与 evidence 同族；渠道用 E1/E2/E3 |
| `brand_affiliations` | 渠道 CSV | 多品牌授权（字符串，可能含多值） |

### 6.5 证据分层 E1–E4 在 UI / 文案上的用法

| 层级 | 含义（本项目约定） | UI 建议 |
|---|---|---|
| **E1** | 品牌/协议组织官方页、官方案例、官方 locator | 「官方」徽章；默认可信展示 |
| **E2** | 行业协会、认证驱动商、权威媒体综述 | 「行业/认证」；可展示 |
| **E3** | 集成商作品集、自述授权、项目页 | 「集成商案例」；展示但勿写成厂商官方承诺 |
| **E4** | 论坛/二手讨论/弱溯源趋势文 | 「社区/讨论」；默认折叠或仅作补充，**不可当规格事实** |

渠道名录：`source_tier` 的 E2（CEDIA bulk）本轮为 **0**——勿在 UI 暗示「已对接 CEDIA 全量名录」。

### 6.6 安全边界（必须写进产品与内容审核）

1. **安装指导停在安全边界**：可写拓扑、机柜规划、协议对接、换商流程；**不提供**市电改线、配电箱作业、攀高危险施工的逐步 DIY 指引。市电一律导向持证电工（核实表 X15）。  
2. **不登录抓取的缺口**：Crestron/Savant/Lutron 官方经销商目录、部分价格与需登录下载的手册——在 App 中应展示为「需经销商/登录门户确认」，**不要**用爬虫或会话绕过补洞。  
3. **付费墙与付费报告**：只用公开摘要；不编造数字（核实表规则）。  
4. **联盟/线索**：若有付费推广，遵守 FTC 披露（核实表 X19）。

### 6.7 已知缺口（开发排期时显式标注）

| 缺口 | 影响 |
|---|---|
| Savant 原生 Matter / 原生 KNX 网关公开 E1 薄 | 融合模块对 Savant 少「官方路径」卡片 |
| 北美本土「KNX 总线 + Control4 局部」大型公开案偏少 | 案例模块可多用欧中东案并标注地域 |
| Lutron 专业线对 Matter 偏保守 | 融合多经 Clear Connect / 主机桥 / 1Home 等 |
| Phase C **非全量目录**；C4 都市圈有 UpperLimit；其他品牌 E1 行数极少 | 找商结果须提示「样本/公开可检索，非全球全量」 |
| 子系统中 ADT 与四老牌深度驱动公开页偏少 | 安防卡片多走 Alarm.com / Resideo 集成叙述 |
| `fusion_pattern` / `app_takeaway_zh` 在 FH001–FH131 可能缺失 | 导入时对空字段回退到 `summary_zh` 首句 |
| `99-raw` 大、未全部清洗 | 不要默认全文检索 raw |
